# Публикация GOLUBKA AVIA на Render

Render запускает один Docker Web Service. FastAPI отдаёт React и API с одного HTTPS-адреса. Docker-образ содержит два CSV прогноза и собранный интерфейс. Аккаунты, сессии и сохранённые сценарии хранятся в отдельной Render PostgreSQL.

## 1. Подключить GitHub

Создайте пустой репозиторий GitHub. Можно выбрать **Private**: сайт всё равно будет публичным, когда Render получит доступ к репозиторию. Дайте GitHub App Render доступ к этому репозиторию.

В корне проекта отправьте подготовленную локальную ветку `render-release` как `main` пустого GitHub-репозитория. Ветка содержит проверенный снимок проекта и отдельный начальный коммит с техническим адресом автора.

```sh
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin render-release:main
```

Подставьте адрес своего репозитория. Перед отправкой проверьте содержимое выпуска через `git show --stat render-release` и `git ls-tree -r --name-only render-release`. Для последующих публикаций добавляйте проверенные изменения в ветку `render-release` и отправляйте её тем же refspec `render-release:main`.

## 2. Создать Blueprint

1. В [Render Dashboard](https://dashboard.render.com/) выберите **New → Blueprint**, подключите репозиторий и выберите ветку `main`.
2. Проверьте, что оба ресурса в регионе Frankfurt используют тариф **Free** и итоговая стоимость равна нулю. Бесплатный веб-сервис засыпает после 15 минут без запросов. Бесплатная PostgreSQL истекает через 30 дней с даты создания. Для более длительного хранения потребуется отдельно согласовать переход на постоянную базу.
3. После подтверждения дождитесь статуса **Live** и скопируйте HTTPS-адрес из панели сервиса.

Blueprint передаёт внутренний адрес базы через `DATABASE_URL`. Внешний доступ к БД закрыт. Render предоставляет `PORT` и `RENDER_EXTERNAL_URL`. Если используется собственный домен, задайте `PUBLIC_ORIGIN` равным его полному HTTPS-адресу без завершающего слеша и открывайте приложение по этому адресу. `SECURE_COOKIE=1` включён в Blueprint. На Render приложение завершает запуск при отсутствии PostgreSQL или HTTPS-настроек. `/api/health` проверяет доступность прогнозных данных и БД.

Храните реальные реквизиты только в Environment на Render. `.env.example` содержит настройки локального Docker Compose. В исходники и Docker-образ входят только файлы проекта и данные прогноза. Локальную SQLite с существующими аккаунтами и сценариями на сервер не переносим. Новая PostgreSQL начинается с пустых таблиц. При перезапуске или пересборке веб-сервиса данные остаются в той же PostgreSQL. Для отката выпуска используйте **Rollback** веб-сервиса, сохраняя его подключение к базе.

## 3. Проверить публичный выпуск

В приватном окне откройте адрес из Render и проверьте:

1. HTTPS, `/api/health` со статусом 200, загрузку Главной и прямые переходы на `/pricing` и `/scenarios`.
2. Прогноз на Главной и Pricing Lab, расчёт по другой цене, оба календаря, смену даты и подсказки всех графиков.
3. Зарегистрируйте тестовый аккаунт, сохраните сценарий, выйдите и войдите снова. Проверьте атрибуты cookie `Secure` и `HttpOnly`.
4. В отдельном сеансе зарегистрируйте второй тестовый аккаунт. Первого сценария в списке быть не должно, а чтение, изменение и удаление через его ID должны возвращать 404.
5. Перезапустите **веб-сервис** в Render. После восстановления `/api/health` войдите первым аккаунтом и проверьте, что сценарий и избранное сохранились. Удалите тестовый сценарий.

Сайт считается опубликованным после проверки реального публичного HTTPS-адреса.

## Локальная проверка контейнера

При установленном Docker запустите `docker compose up --build -d`. Откройте `http://127.0.0.1:8000/api/health` и проверьте интерфейс. Compose использует отдельный том для локальной SQLite. На Render используется PostgreSQL из Blueprint.
